# Realtime fixes — September 18, 2026

Implements the confirmed findings from REALTIME_DIAGNOSIS_2026-09-18.md, covering human opponents and bots.

- Live servers build navigation graphs in one worker thread, never synchronously on the match loop. A bounded 32-entry cache reuses identical geometry across rooms and distinguishes character and movement modifiers. While a graph is pending, bots use surface-only navigation for same-platform movement/combat, then adopt the completed graph. Failed worker requests retain that safe fallback and retry after 30 seconds. The offline simulator intentionally retains synchronous deterministic navigation; worker equivalence has a separate integration test.
- Body configuration resolution now copies its scalar fields directly, removing recursive cloning from physics probes.
- Remote Ninja basic attacks mark the shared one-shot animation state; snapshot rendering now honors sprite locks, including swarm releases and Huntress specials. Unhandled character actions correctly report false instead of locking an unrelated movement animation. Death remains on its separate presentation path.
- Ninja confirmation corrections preserve outbound direction, while real terrain turns, returns, rejection and terminal packets remain authoritative. Under high latency this can briefly slow or hold the visual while the server trajectory catches up; it does not move server hitboxes or trust client launch timestamps.
- Fresh remote Ninja/Huntress launches bridge the displayed actor position to the authoritative path over 100 ms. This explicitly accommodates buffered actors without adding a matching delay to combat/hit feedback. Stale launches and offsets over 200 px bypass the bridge. Huntress packets add an optional launch-origin field; older clients ignore it.
- Remote extrapolation is capped at 250 ms instead of one second, limiting overshoot during outages. The player you control still uses its existing local movement path.
- Network-test summaries distinguish arrival gaps from source publication gaps, count packets handled by newer adapters, and report unclamped server-loop gaps. Timing severity uses recent sample-window maxima and labels its score as a heuristic. Navigation cache misses report character, modifiers, build duration and queue time.
- `window.__BB_NINJA_DIAGNOSTICS__()` exposes a bounded 120-event correction/backtracking history. Existing Huntress diagnostics remain available. Sprite `_bbAnimationState.lastInterruption` and `interruptionCount` record action interruptions for focused animation tracing.

Validation before deployment: 75 network tests passed; the worker integration test passed. The full suite passed 690 of 692 tests. The two failures (duck art cell assignments and currency reward sound selection) were reproduced against the unchanged starting commit a15dd11. Production webpack build passed. New regressions cover the remote human animation path, repeated attacks and skins, owner confirmation at 10/50/150/250/350 ms steady RTT, genuine returns, moving remote Huntress launch alignment, source/arrival timing separation, extrapolation bounds, worker yielding, cross-room reuse and modifier-specific route equivalence.

This is a targeted correction of demonstrated faults. It does not promise flawless play through arbitrary network outages or a complete unification of every older character protocol. A synchronized two-browser human playtest remains useful for visual feel; the implementation tests exercise both owner and remote-human presentation directly without browser automation.
